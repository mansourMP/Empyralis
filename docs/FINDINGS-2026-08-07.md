# Findings — 2026-08-07 audit session

Written so nobody re-researches these. Each entry says what was found, whether
it is fixed, and where the evidence is. Line numbers drift — treat them as
starting points, not gospel.

**Fixed and deployed** entries need no further work. **Open** entries are real
and unresolved. **Decided** entries record a judgment call so it is not
relitigated.

---

## Fixed and deployed

### Agents could not touch their own tasks on the default engine
`project_task__*` (list/update/comment/create) lived only in the lazy Tier-2
registry, reachable solely via `query_tool_registry` — which
`claude_agent_sdk_bridge.py`'s `_UNSUPPORTED_TOOL_NAMES` filters out. Removing
the discovery tool stranded every tool behind it (~36), not just the three the
docstring admits to. Assigning a task woke the agent into a turn where it could
not act on that task. **This was the product's core loop, broken.**

Three independent gates had to be fixed, not one: the Tier-1 bundle, the
specialist connector gate (`"project_task"` was never in `CONNECTOR_CATALOG`,
so the binding could never pass), and an execution-time `specialist_guard` in
`direct_tool_execution_service.py` that would have refused the call even with
the schema present. Grant is now by **project membership**, mirroring the
existing `fleet__*` carve-out.

### The system prompt advertised tools the engine could not reach
`sage_instruction_compiler_service.py`'s "## Callable Tools" manifest listed
Tier-2 tools and instructed the model to call `query_tool_registry` — on an
engine where that call is impossible. The manifest had zero awareness of engine
selection. Now engine-aware.

### Reasoning effort was inert
`ClaudeAgentOptions.effort` was never set; `reasoning_effort` only reached
tool-internal LLM calls. Setting "High" changed nothing. Now wired, all five SDK
levels (`low|medium|high|xhigh|max` — `max` was missing from our vocabulary).
Note `xhigh` degrades to `high` on non-Opus-4.7 models, per SDK docs. Effort is
dropped by the adapter for non-Anthropic providers — deliberate: reasoning comes
from the SDK, we do not maintain per-provider translation tables.

### SDK-engine turns recorded no usage at all
`handle_sage_chat`'s SDK branch never called `record_usage_from_context`. Only
the gateway/CLI-subscription and Sage-fallback paths metered. "Cost today" and
the per-model breakdown had **no rows to sum** for ordinary turns. Now metered,
with cache-read/cache-creation as separate columns.

### Context percentage was ~5x too high
`get_context_usage()` returns the `claude` CLI's own `maxTokens`, computed from
its internal model table. For `model="deepseek-v4-pro"` — not a real Anthropic
model id — it silently falls back to **200,000**, while our catalog declares
**1,000,000**. Verified empirically with a local harness, not inferred. Now
overridden server-side from `provider_profiles.context_window_for_model()`,
leaving the CLI value alone when we have no catalog entry (never fabricate).

### SDK-engine turns had no cost ceiling
The legacy engine enforces one mid-loop; the SDK bridge set nothing. Now wired
via `ClaudeAgentOptions.max_budget_usd`. Note the per-agent override
(`deployed_agent_cost_cap_service`) only reaches background automated runs —
**interactive chat gets one flat $1.00 platform default**.

### Bedrock/Vertex credentials went to the public Anthropic API
`_CREDENTIAL_ENV_KEYS` declares seven cloud-auth flags
(`CLAUDE_CODE_USE_BEDROCK`, `_VERTEX`, `_FOUNDRY`, `_ANTHROPIC_AWS`,
`_ANTHROPIC_GOOGLE_CLOUD`, `_MANTLE`, `CLAUDE_CODE_OAUTH_TOKEN`) and set
**none** of them. Credentials fell through to the generic `api_key` branch and
were sent to `api.anthropic.com`. Bedrock now routes correctly. Also closed a
second leak: our own ambient AWS credentials could reach an unrelated tenant's
subprocess.

### Gateway ignored newly-available capabilities until restarted
Execution authorization read the static `capabilities` array from the initial
`hello`, not the live per-heartbeat `capability_readiness` the gateway already
sends. Start Docker after the gateway connects → still refused until the daemon
restarts. Reproduced end-to-end, then fixed read-side.

### Credit exhaustion showed "Something went wrong. Try again."
`classify_error`'s bucket matched `"ai limit"`, but the message had been
reworded to `"AI usage limit reached"` on 2026-06-30 — `"usage"` broke the
substring. Silently broken five weeks. Now carries the stable `cap_reached`
code rather than free text.

### The e2e suite could not log in
`tests/e2e/support/auth.ts`'s `loginAsOwner` waited on `data-workstation-shell`
— a UI removed months ago — and navigated to `/sage`, which redirects. **Nothing
using it could pass login**, and 14 spec files use it. Fixed; 12 tests retired
across 3 files whose target surfaces no longer exist.

## Open — real, unresolved

### Channels: replying is automatic, and the only guard is a prompt
`sage_reply_dispatcher.py` sends the turn's raw text unless the model happened
to emit `[SILENT]`/`NO_REPLY`. The envelope header *asks* the model to stay
quiet unless addressed — advisory text it can override, and did. This caused a
real incident: an agent in a public Telegram channel replied to posts, then to
the "who is this bot?" replies, in a loop, until the account was banned.

- A real mention-gate exists (`mention_gating_service.py`) but
  `DEFAULT_REQUIRE_MENTION = False` — a deliberate reversal of a stricter
  default that had itself been added to fix an earlier group-spam incident.
  **Same failure mode, twice.**
- Broadcast protection covers only true Telegram broadcast chats, not large
  public supergroups.
- **No loop breaker** for Telegram/WhatsApp. The only circuit breaker
  (`SELF_CHAT_BREAKER_MAX_TURNS`) is scoped to the owner's self-chat.
- `is_bot` is hardcoded `false` for Telegram/WhatsApp. Discord reads it properly.
- `group_policy`/`require_mention` exist in storage with a full resolver, but
  `_persist_agent_group_policy_config` is **called from nowhere** — no route, no
  UI. An owner cannot configure any of this today.

DMs are unaffected — a 1:1 has no audience to cascade into.

**Proposed, not decided:** keep auto-send for DMs; require an explicit
`channel__reply` tool call for group/broadcast surfaces. `InboundEnvelope.surface`
already computes that distinction deterministically before the model runs. A
per-chat reply counter is the safe subset — it is correct regardless of which
way the group-default question is decided.

### Vertex removal is half-done
Provider-profile edits landed; the SDK-bridge cleanup did not (interrupted by a
disk-full incident). Uncommitted in a worktree. Bedrock must stay.

### Session tables were never pruned
MAN-140 fixed the reconnect *rate* (commit `83ec99fe1`) but its cleanup only
touched the gateway's local SQLite. Postgres `agent_sessions`/`runtime_sessions`
were never covered — every reconnect ever is still stored. ~14 session rows per
conversation turn.

### Telemetry outgrows conversations ~109:1
Per turn: ~65 `agent_secret_access_events`, ~26 `activity_ledger_events`, ~14
session rows, ~4 trace rows — versus **1** row of actual conversation
(~1.9 KB/turn; a million turns is ~2 GB). Conversations are not the storage
problem. A retention policy is merged but **deployed disabled**
(`EMPYRALIS_TELEMETRY_RETENTION_ENABLED=0`) pending a decision. It protects
conversations, tasks, memory, credits, and usage; the security audit trail has
its own longer 180-day window on a separate variable.

Two earlier retention attempts exist as **dead code**:
`retention_enforcement_job.py` (MAN-80) and
`session_service.prune_expired_sessions` — both with zero callers.

### Public claims that are narrower than stated
Posted on NousResearch/hermes-agent#527. All four are *partially* true:
- **"Owner/Admin/User/Guest tiers"** — actually three (`viewer/member/owner`).
  "Guest" does not exist; "admin" is an ad-hoc synonym for owner.
- **"Enforced below the agent"** — TRUE, and it is the real differentiator:
  restricted tools are deleted from the payload, not described as forbidden.
  But it is keyed on *agent role* and *channel audience*, **never** the human's
  RBAC tier. Two teammates with different roles get identical tool access.
- **"Spend limit enforced below the agent"** — only became true on the SDK
  engine on 2026-08-07, after the post.
- **"Isolation is at the database"** — true at the **tenant** boundary (37
  tables, RLS FORCE), not the **agent** boundary. Two agents in one workspace
  share rows with no RLS between them. `stage_4b_agent_isolation.sql` adds no
  RLS despite its name. ~118 `bypass_rls=True` call sites make it a
  code-review trust boundary. MAN-206/300/301 showed RLS missed a
  foreign-key-shaped cross-tenant hole that needed an application-layer fix.

### Unwired SDK capabilities
Confirmed present in `claude_agent_sdk` and never set: `hooks`,
`thinking`/`max_thinking_tokens`, `fork_session`, `enable_file_checkpointing`,
`task_budget`, `output_format`, `include_partial_messages` (now set),
`betas`, `can_use_tool`, native `agents=`.

`permission_mode="plan"` — the "planning" seen in Claude's own app — is
deliberately **not** wired: it works by pausing for approval, which this
product's no-approval-system law forbids. If planning is wanted, it must be
plan-as-artifact (the agent writes its plan where the owner can see it and keeps
working), never a blocking gate.

`betas`/1M-context is not the easy win it looks like: it is Anthropic-specific
(a no-op for DeepSeek) and enabling it without fixing the meter's denominator
would make the meter wrong.

### Smaller, confirmed
- Activity attribution credits the **assignee**, not the assigner
  (`project_tasks_service.py` ~1872 and ~1996). `actor_type` compares
  `triggered_by == "agent"` but always receives a UUID, so it is effectively
  hardcoded `"user"`. Also writes a duplicate event on a no-op re-assign.
- `.git` is ~11 GB; each worktree carries its own `node_modules` (~600-900 MB).
  177 worktrees filled the disk to 100% mid-session and killed several agents.
  Nothing prunes them.
- 4 e2e tests still fail against a dead Sage bootstrap wizard.

## Decided

- **Hardware attaches to its owner, never the project.** Per-machine opt-in,
  default off. Now a product law in CLAUDE.md.
- **Vertex is removed. Bedrock stays.**
- **A curated handful of models, not every model.** Flash/Pro tier naming for
  platform credits; vendor disclosed in a subtitle, never the chip.
- **Reasoning comes from the SDK.** No per-provider translation tables.
- **The tab strip is not rejected** — deleted from the web, wanted for the
  future native app. Recoverable at commit `715d7d5b0`.
- **Empyralis is the layer above coding agents.** Never build a coding surface;
  Claude Code / Codex are the execution layer. The board is the contract; the
  chat is the workshop.
